# Selzy Studio — MicBridge Auto Input 1.0.0-rc1

An optional Windows x64 add-on that selects **Steam Streaming Microphone** when an Apollo remote session connects, then restores the previous capture device for each Windows role two seconds after the final session ends. No APK update is required. The existing host and Android packages remain at [v1.0.0-rc1](https://github.com/SelzyStudio/micbridge-stream/releases/tag/v1.0.0-rc1).

Download the complete [add-on ZIP](https://github.com/SelzyStudio/micbridge-stream/releases/tag/auto-input-v1.0.0-rc1), extract it, compare the executable's SHA256 with the release checksum, and run `Install.ps1 -ValidateOnly` followed by `Install.ps1` in PowerShell as your normal Windows user. A custom Apollo log path can be passed with `-ApolloLog`. No administrator permission is needed. Windows x64, .NET Framework 4.x, an existing Apollo host and exactly one active capture device containing `Steam Streaming Microphone` in its name are required. Steam drivers are not included.

Installation uses `%LOCALAPPDATA%\MicBridge\AutoInput` and the current user's `MicBridge-AutoInput` Run entry. Existing installations or conflicting startup entries are rejected without overwriting. Existing users do not need to reinstall. For an upgrade, run Disable.ps1 in the installed folder, wait for successful restoration and removal of original-input.json, then preserve the old folder elsewhere before installing. Do not move or remove a folder with a pending recovery journal. To disable, run Disable.ps1 from the installed folder; recovery files are retained. Reconnect an unavailable original microphone and retry restoration.

**The executable and scripts are not Authenticode-signed.** Windows may display warnings or enforce script execution policies; the installer does not bypass them. A Defender scan with no detections is not a safety guarantee. Do not disable antivirus or add exclusions.

The helper reads Apollo's current log every 250ms and samples capture-device availability/manual changes every second. It does not record or transmit audio, change playback/volume/mute, modify Apollo configuration, or update the phone. Local status and recovery files can contain device names/IDs and process/path details; redact before sharing. It follows the specific Apollo log format; multiple sunshine processes, an unreadable or over-64MiB log, and future format changes can prevent detection. Programs pinned to a specific microphone do not follow Windows defaults. Abrupt termination cannot restore immediately; the next startup uses the persisted journal. A disappearance and reappearance between one-second observations can be missed.

Build.ps1 compiles the included source into `build` and runs 39 fake-adapter regression tests. `tests\Run.ps1` runs additional edge cases without changing real audio devices. A rebuilt PE can have a different hash. Initial phone connect/disconnect testing passed; the final reviewed helper passed virtual regressions and real Windows capture-switch/restore and playback-preservation checks, but the phone test was not repeated after the final review. New distribution scripts were checked separately without reinstalling the current working system. Other physical PCs/phones are not verified. See VALIDATION.json for exact scope.
